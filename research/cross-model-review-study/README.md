# Cross-model PR review delta study (Spec R)

> One-shot research artifact, not a kuroboto product feature.
> Goal: empirically test whether cross-lineage PR review (different model
> families reviewing the same diff) catches findings that any single-lineage
> fleet (Claude-only / GPT-only) systematically misses.
> Decides whether kuroboto pivots to "cross-LLM autonomous PR pipeline" as
> the headline feature.

## Status

- **M1** ✅ Harness setup (`promptfooconfig.yaml` + `cli-provider.cjs`), smoke v2–v5 on PR #29
- **M2** 🚧 Full corpus eval (PR #29, #30, #21, #19) across 10 providers / 7 lineages
- **M3** 🚧 Analysis (`analyze.ts`, `delta-report.md`)
- **M4** ⏳ Decision: pivot to cross-LLM headline OR drop angle

See [`docs/specs/cross-model-review-delta-study.md`](../../docs/specs/cross-model-review-delta-study.md)
for the full spec and decision rule.

## Architecture

Three-tier provider strategy — same review prompt across all, only the
inference path differs:

```
                                       ┌─ claude-sonnet-4.6  ─┐
                                       ├─ claude-opus-4.7    │
        Tier 1: OAuth CLIs ($0/call)   ├─ codex (gpt-5.x)    │── Anthropic Pro / ChatGPT Plus / Google
        via cli-provider.cjs           ├─ gemini             │   subscriptions; promptfoo spawns
        subprocess wrapper             └─ copilot            │   the CLI as a child process
                                                              │
                                       ┌─ kimi-k2.6          │
        Tier 2: OpenCode Zen API       ├─ minimax-m2.7       │── Pay-per-token Zen credits;
        (China-lineage models)         └─ glm-5              │   max_tokens=8000 + stream=true
                                                              │
        Tier 3: Ollama local           ┌─ deepseek-coder:6.7b│── $0, runs on the dev box;
        (open-weight controls)         └─ llama3.3 (70b)     │   smaller params, JSON-discipline
                                                              │   weaker than cloud tier
```

The `cli-provider.cjs` wrapper exists because promptfoo's openai-shim cannot
authenticate against CLIs that use OAuth or wrapped credentials (claude,
codex, gemini, copilot). It spawns the binary, pipes the rendered prompt to
stdin (or via `${PROMPT}` placeholder in args), and returns stdout.

## Reproduction

Prereqs: `node` (≥20), `npx`, the eight CLIs installed and authenticated
(`claude`, `codex`/`codex.cmd`, `gemini`/`gemini.cmd`, `copilot`,
`opencode`, `ollama`), and the OpenCode Zen API key (read from
`~/.local/share/opencode/auth.json`).

```bash
cd research/cross-model-review-study

# Set Zen API key from opencode auth (the same key works for opencode-go too)
export OPENCODE_ZEN_KEY="$(jq -r '.opencode.key' ~/.local/share/opencode/auth.json)"

# Verify all providers respond — single PR, all 10 providers
npx promptfoo eval --filter-first-n 1 --output results/smoke.json

# Full eval — 4 PRs × 10 providers = 40 reviews (≈30-60 min wall)
npx promptfoo eval --output results/eval-vN.json

# Generate delta-report.md from results
npx tsx analyze.ts results/eval-vN.json --out results/delta-report.md
```

Promptfoo's cache key includes prompt hash + provider config + input hash;
`--no-cache` forces fresh runs (used for first eval; subsequent re-runs
hit cache for unchanged providers).

## Files

| Path | Purpose |
|---|---|
| `promptfooconfig.yaml` | Eval definition: 10 providers, 4 PRs, JSON-extract assertion |
| `prompt.txt` | The review prompt — sourced verbatim from `.github/workflows/claude-code-review.yml` for parity with production |
| `providers/cli-provider.cjs` | Subprocess wrapper for OAuth-CLI providers |
| `prs/<num>/diff.patch` | Captured PR diff (`gh pr diff <num>`) |
| `prs/<num>/spec.md` | Linked spec under `docs/specs/` |
| `prs/<num>/context.md` | `AGENTS.md` snapshot |
| `analyze.ts` | Per-provider stats + Jaccard overlap matrix + cross-lineage delta |
| `results/eval-*.json` | Promptfoo raw output (one per eval run) |
| `results/delta-report.md` | Generated by analyze.ts — TL;DR verdict + tables + qualitative examples |
| `results/findings.json` | Machine-readable digest (per-review findings list) for further analysis |

## Adding a provider (v2)

1. Decide tier:
   - **Tier 1** if there's a CLI with OAuth/subscription auth → add to
     `providers:` block with `id: file://providers/cli-provider.cjs` and
     give it a unique `label`. The wrapper handles spawn + timeout + output
     stripping.
   - **Tier 2** if it's reachable via an OpenAI-compatible API → use
     `id: openai:chat:<model>` with `apiBaseUrl` + `apiKeyEnvar`.
   - **Tier 3** if it runs locally on Ollama → `id: ollama:chat:<model>`,
     ensure the model is pulled (`ollama pull <model>`).

2. Add lineage attribution to `analyze.ts`'s `LINEAGE` map so the delta
   calc can group it correctly.

3. Run smoke (`--filter-first-n 1`) to verify the provider returns parseable
   review JSON before launching the full eval.

## Decision rule (from the spec)

| Cross-lineage uplift over Claude-only baseline (P0/P1) | Verdict |
|---|---|
| ≥20% unique critical findings | **H1 supported** — pivot kuroboto roadmap to cross-LLM PR pipeline |
| 10–20% partial uplift | Configurable feature, not headline. Reposition around privacy/sovereignty |
| <10% uplift | **H0 not rejected** — drop cross-model angle, position as solo-dev tool |

## Caveats

- **Single run per (provider, PR)** — variance not measured. Real
  significance requires N≥3 per cell.
- **No human ground-truth labels** — precision/recall not computed.
- **Size confound** — cloud models (100B+ params) vs Ollama controls (7-70B)
  not directly comparable on capability. Analysis bins by tier.
- **Copilot label** — wraps an undisclosed model (often Anthropic). Reported
  as `GitHub-wrapped` lineage to flag the ambiguity.
- **Small corpus** (4 PRs) — broad signal only; fine-grained breakdowns
  need a larger sample.
